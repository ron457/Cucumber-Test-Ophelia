# Ophelia BDD Commerce Suite

A scalable end-to-end test automation framework built using **Playwright**, **Cucumber (BDD)**, and **TypeScript**, following the Page Object Model (POM) design pattern. Built and tested against the [Practice Software Testing — ToolShop Demo](https://practicesoftwaretesting.com).

## Framework Architecture

```
Feature Files (Gherkin)
        ↓
Step Definitions (TypeScript)
        ↓
Page Object Methods (shop.page.ts)
        ↓
Locators (shop.locator.ts) + Test Data (shop-data.json)
        ↓
Playwright Browser Actions
        ↓
Screenshots + Cucumber HTML Report
```

Design patterns used:

- **BDD** — Behaviour Driven Development with Gherkin scenarios
- **POM** — Page Object Model for reusable UI actions
- **Data-Driven Testing** — all inputs externalised in JSON
- **Modular Structure** — tests folder is the only folder that changes when targeting a new site

    "country": "IN",
    "postalCode": "123456",
    "houseNumber": "10",

  },

## Running Tests

**Run all tests**
```bash
npm test
```

**Run by module tag**
```bash
npm run test:smoke          # Homepage + cart smoke
npm run test:login          # Login flow
npm run test:register       # Registration flow
npm run test:cart           # Cart flow
npm run test:checkout       # Authenticated checkout
npm run test:checkout-guest # Guest checkout (no account needed)
npm run test:regression     # Full regression suite
```

**Generate HTML report after regression**
```bash
npm run test:regression:report
```

Report opens at: `reports/html-report/index.html`

## Test Scenarios

| Scenario | Tags | Flow |
|---|---|---|
| Homepage and cart | `@smoke` `@cart` | Open homepage → browse → select product → add to cart → validate |
| Login | `@login` `@auth` | Navigate to login → enter credentials → assert authenticated |
| Register | `@register` `@auth` | Navigate to register → fill form → assert authenticated |
| Checkout (authenticated) | `@checkout` `@regression` | Product → cart → sign in → billing → payment → confirm |
| Checkout (guest) | `@checkout-guest` `@regression` | Product → cart → login attempt → error → guest form → billing → payment → confirm |

## Guest Checkout Flow

The guest checkout scenario is designed to work even when test credentials are invalid or the account is locked. The flow:

1. Attempts login with credentials from `shop-data.json`
2. Detects `Invalid email or password` error (10s timeout)
3. Automatically clicks **Continue as Guest** tab
4. Fills guest email, first name, last name
5. Submits and confirms guest session
6. Proceeds through billing → payment → **finish** (first click)
7. Asserts `payment-success-message` visible
8. Clicks **finish** again → final confirmation page
9. Asserts `Thanks for your order! Your...` text

Run it with:
```bash
npm run test:checkout-guest
```

## Screenshots & Reports

Screenshots are captured **automatically at every step** via the `AfterStep` hook and saved to `reports/screenshots/`.

To generate the full HTML report:

```bash
npm run report
```

The report includes browser info, platform, execution timestamp, and all scenario results with embedded screenshots.

## Adapting to a New Site

The framework is built to be reusable. To target a different e-commerce site:

1. Update `Assets/test-data/shop-data.json` with new URL and test data
2. Update `utilities/locators/shop.locator.ts` with the new site's selectors
3. Update `tests/pages/shop.page.ts` if the UI flow differs
4. Update `tests/features/shop.feature` with new scenarios

No changes needed outside the `tests` folder and `utilities/locators` for most sites.
